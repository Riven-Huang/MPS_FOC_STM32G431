# program 故障定位、三环测试与 VOFA

本文按当前 `program/App` 实现编写。源码检查能确认触发逻辑，不能确定板上本次故障原因；需结合故障位、停止位置和实际测量。调参通过 Keil Watch 写 `g_cmd`；当前串口只有遥测，没有接收调参命令。

## 1. 先区分停在哪里

| 现象 | 含义 | 恢复方式 |
| --- | --- | --- |
| `g_fb.state` 为 3，程序和遥测仍运行 | 电机 FAULT 保护锁存 | 排除故障源，再写 `g_cmd.clear_fault` 为 1 |
| 停在 `Error_Handler()` | HAL 初始化、校准或启动操作失败；该函数关闭中断并死循环 | 查看调用栈定位失败的 HAL 调用，修复后复位；清故障命令无效 |
| 停在 `HardFault_Handler()` 等异常处理函数 | CPU 异常 | 保存调用栈、异常现场及 SCB 故障寄存器，定位访问/栈/指令问题后复位；清故障命令无效 |

`Error_Handler()` 的调用点包括时钟、GPIO 以外的多种外设初始化，以及 `program.c` 中 ADC 校准、PWM/互补 PWM、ADC DMA、TIM6 和注入组启动。代码没有保存具体错误编号，必须从调用栈返回到调用点，查看对应 HAL 返回状态及外设句柄。进入函数的死循环后，单纯继续运行不能恢复。

运行电机时不要暂停 CPU 来改参数。源码没有显式配置调试暂停时的定时器冻结，也没有在上述异常入口主动关闭功率级；暂停控制计算不能当作可靠停机。先在持续运行状态下写 `g_cmd.run` 为 0，确认 `g_fb.state` 回到 0，再打断点。FAULT 锁存时写 `run` 为 0 本身不会解除锁存。

## 2. 当前全部电机故障位

`g_fb.fault_bits` 是可叠加的位掩码，建议在 Watch 以十六进制显示。例如 16 表示 `0x10`，3 表示 `0x01 | 0x02`。当前 VOFA 不发送故障位，请在 Watch 查看。

| 故障位 | 源码触发条件 | 检查及处理 |
| --- | --- | --- |
| `0x01` / 1，驱动故障 | PB15 的 `N_FAULT` 为低，所有状态都检查 | 看 `g_fb.drv_fault`；核对驱动供电、故障脚、相线及功率级。只有一根故障输入，软件无法区分驱动内部具体故障类型 |
| `0x02` / 2，相过流 | 零偏就绪后，任一相电流绝对值超过 10 A，单拍即可触发 | 查三相原始码、零偏、采样极性、相序、电角度、PI 参数和负载；不要用提高保护阈值掩盖问题 |
| `0x04` / 4，母线过压 | 1 kHz 慢任务中，滤波母线电压超过 65 V，待机也检查 | 对比实际母线和 `g_fb.vbus_v`；检查分压配置。若出现在减速/反转，检查回灌并降低速度和位置速度上限 |
| `0x08` / 8，母线欠压 | 滤波母线低于 12 V，且状态不是 IDLE，包括 FAULT | 检查母线是否上电、电源是否限流跌压、连接和 ADC2 DMA 数据。仅上逻辑电时不要启动 |
| `0x10` / 16，编码器失效 | ALIGN 中，或需要编码器的 RUN 模式中，编码器无效 | 看 `enc_valid`、`enc_err`、`enc_reject` 和 `enc_samples`；检查供电、SPI 和磁铁安装。连续 4 次坏样本会撤销有效标志，单帧跳变门限为 1024 计数，约 5.625° |

故障位是累计结果，并不保存第一故障的时间和波形。例如先发生驱动故障，随后断掉母线，可继续叠加欠压。停机时环路、观测器和对齐数据会复位；停机后看到的电流或角度不能代替触发前的现场。

当前没有独立的软件过温、超速、堵转、对齐失败、快环超时或 ADC 失效故障位。`ntc_c`、`loop_us_max`、`overrun_cnt` 是观测量；驱动芯片自己的保护只能汇总到 `0x01`。编码器样本停止更新但仍保留有效标志时，现有代码也没有独立的样本超时保护。

### 为什么可能频繁进入保护

- 本地 `CFG_ENC_DIR_SIGN` 已由仓库的负方向改为正方向。方向是否正确取决于实际相序和安装，不能只凭修改记录下结论。若刚改后闭环变得抖动、无力或过流，优先验证这一项；本次未改动它。
- 对齐使用固定 `CFG_ALIGN_UD_V`（默认 1.2 V），名义持续约 0.8 s，旁路电流 PI，因此不受 `g_cmd.iq_lim_a` 限制。对齐电流只由 \(1.5R_{ph}\) 通路决定，且全程不产生有用功，是纯铜耗：电压越高，发热和过流余量占用越大。若一直在 ALIGN 阶段过流，应先查电阻、接线、采样，再评估 `CFG_ALIGN_UD_V`，而不是只调运行电流给定；反过来，若转子锁不住、`g_fb.align_ofs_rad` 每次启动都不一致，则要加回电压或延长 `CFG_ALIGN_HOLD_TICKS`。
- 过流为单拍判定，驱动故障脚也没有软件去抖；真实瞬态和采样/接线问题都需要检查。
- 调试暂停后再运行，编码器角度可能已明显变化，恢复后的跳变剔除可能触发编码器故障。是否属于这一情况需看 `enc_reject`。
- 清故障实现只检查 `N_FAULT` 已恢复，并不检查所有故障源。过流、过压仍在时会重新锁存；欠压可能先回 IDLE，下一次启动又触发。

### 正确恢复顺序

1. 写 `g_cmd.run` 为 0，记录故障位、`drv_fault`、母线电压、三相电流、编码器有效性及错误计数。
2. 排除对应故障源。确认母线恢复正常、驱动故障输入为 0、电流反馈合理、编码器能持续更新。
3. 保持程序运行，写 `g_cmd.clear_fault` 为 1。这是一次性请求，代码会自动清零它，同时清零 `run`。
4. 确认 `fault_bits` 为 0、`state` 为 0。若失败，重新检查故障源；不要反复强清。
5. 设置模式、较小目标和限幅，最后写 `run` 为 1。闭环重新启动会再次对齐。

## 3. 三环按什么顺序测

电流环 → 速度环 → 位置环。速度模式内部包含电流环，位置模式内部包含速度环和电流环，不需要分别打开三个使能开关。

首次测试先卸去力臂和外部负载，固定好电机，留出转动空间；保持待机直到 `offset_ready` 和 `enc_valid` 都为 1、`fault_bits` 为 0，母线测量与实际一致。静态三相电流应接近零。关功率级时软件会把反馈中的两轴电流置零，因此静态零偏检查必须看三相电流。

下表各字段通过 Watch 逐项修改，每次先停机并确认状态回 IDLE，再设模式和参数，最后启动。模式的数值对应 `motor.h` 枚举。

### 3.1 电流环：CURRENT，模式 3

| 字段 | 起步设置 |
| --- | --- |
| `g_cmd.mode` | 3 |
| `g_cmd.id_a` | 0 A |
| `g_cmd.iq_a` | 0 A |
| `g_cmd.iq_lim_a` | 1 A，仅作为保守起点，仍需符合电机允许值 |
| `g_cmd.run` | 最后置 1 |

等 `state` 由 1 进入 2、`align_done` 为 1，再把 `iq_a` 从 0 小步改到 0.1 A、0.2 A，然后回零。显示 CH0/1 的两轴实际电流，与 Watch 中的 `id_ref_a`、`iq_ref_a` 对照；在 Watch 查看 `ud_v`、`uq_v` 和 `volt_lim_v`，判断是否进入电压限幅。

电流模式控制转矩，不控制速度；空载小电流也可能持续加速，因此只做短时测试并及时回零、停机。若需要锁轴测电流阶跃，应使用合适的机械夹具，不能用手抓轴。

先保持较小积分、调比例，再逐步增加积分以减小稳态误差。出现持续振荡、异响或明显交叉轴电流，先停机检查角度与采样。默认 `cur_kp` 约 1.288、`cur_ki` 约 2277.65，是当前配置的计算初值，不是新硬件的验收结论。

**通过条件：** 稳态电流随小给定变化、另一轴接近零，没有持续振荡、长期电压饱和或新增保护。约 333 Hz VOFA 只能检查趋势，不能验证 500 Hz 电流环带宽和毫秒以下阶跃；精细整定需高速同步采样或示波器。

### 3.2 速度环：SPEED，模式 4

停机后设 `mode` 为 4，`iq_lim_a` 为 1 A，`spd_rpm` 为 0，再启动。对齐完成后依次试 20、50、100 rpm，稳定后回零，再从小幅负转速检查反向。以上均为转子侧速度，当前减速比为 8，100 rpm 转子对应 12.5 rpm 输出轴。

CH2 是输出轴转速，与转子侧给定比较时需换算减速比；斜坡后的转子速度给定 `spd_ref_rpm` 在 Watch 查看。CH0/1 用来检查实际电流。电流给定长期达到限幅时，先检查负载、角度和可用电压，再讨论增益，不要只增加积分。

先调 `spd_kp`，再逐步加 `spd_ki`。当前默认约 0.01346 和 1.26895；PI 内部在电角速度域运行，不要直接套用机械速度域的增益。低速观测包含量化抑制，20 rpm 适合检查方向，不宜仅凭这一工况定最终参数。

**通过条件：** 正反向符号正确，能稳定跟随小阶跃，无持续猎振，电流和母线不触发保护。先减到零再反向，在 Watch 观察减速时 `g_fb.vbus_v` 是否抬升。

### 3.3 位置环：POSITION，模式 5

停机后设 `mode` 为 5、`iq_lim_a` 为 1 A、`pos_spd_lim_rad_s` 为 0.5、`pos_ki` 为 0，再启动。0.5 rad/s 是首次测试的较低输出轴速度上限；源码默认 8 rad/s 不适合作为首次位置阶跃起点。

**进入位置模式时，程序会把 `g_cmd.pos_deg` 改写为当前位置。** 等状态到 RUN 后再修改目标，先相对当前显示位置增加约 2°～5°，再回到起点；稳定后再扩大到约 10°，不要一开始做 90°/180° 大阶跃。

CH3 显示位置反馈，与 Watch 中的 `g_cmd.pos_deg` 对照，同时看 CH2 的输出轴转速和 CH0/1 的实际电流。位置反馈为输出轴 0～360° 包绕角，跨零会有显示跳变，控制按最短角误差运行。编码器在转子侧，输出轴位置来自解算；停机/故障后的观测复位和重新对齐意味着它不是跨重启保留的输出轴绝对位置。

先调 `pos_kp`，再评估测速阻尼 `pos_kd`，保持 `pos_ki` 为 0 起步。默认 `pos_hold_en` 为 1，保持逻辑进入门限约 1.2°、退出门限约 1.8°，因此不能把这一区域的残余位置误差都归结为比例太小。需要分离保持逻辑影响时，可在低速小步进下暂置 `pos_hold_en` 为 0 对照。

**通过条件：** 小步进方向正确，能稳定停住，无持续往复振荡，速度、电流与母线均正常。精度和稳定时间应按实际机构要求记录，代码没有替你定义验收标准。

## 4. 新 VOFA 通道表

串口：USART1，115200、8N1，协议 JustFloat，周期 3 ms，名义发送频率约 333 Hz。5 路 float 加 4 字节帧尾，共 24 字节，每帧理论串行传输约 2.08 ms，带宽占用约 69.4%。当前波特率下不能直接改成 2 ms，否则发送忙时会丢帧。

| 通道（从 0 开始） | 来源 | 含义 / 单位 |
| --- | --- | --- |
| 0 | `g_fb.id_a` | \(i_d\) 实际电流 / A |
| 1 | `g_fb.iq_a` | \(i_q\) 实际电流 / A |
| 2 | `g_fb.spd_out_rpm` | 输出轴转速 / rpm |
| 3 | `g_fb.pos_out_deg` | 输出轴位置，0～360° 包绕 / ° |
| 4 | `g_fb.enc_deg` | 编码器机械角，0～360° / ° |

给定、电压、故障与统计量通过 Keil Watch 查看。建议按电流、速度、位置和角度分别显示，避免不同单位共享纵轴。角度包绕跳变属于正常显示行为；高速角度和电流纹波仍可能混叠，约 333 Hz 遥测不足以验证 500 Hz 电流环带宽。

反馈复制使用短临界区，避免快环打断一帧的复制；速度、位置和机械角显示量仍按原有 1 kHz 慢任务更新。关功率级时软件会将两轴电流反馈置零，静态零偏检查请在 Watch 看三相电流。实际发送连续性和中断延迟需上板确认。
